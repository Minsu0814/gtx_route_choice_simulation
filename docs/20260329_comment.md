## 1. 교수님 코멘트와 검토 결과

### 1.1 코멘트 요약

1. 퍼스트/라스트 마일 도보 데이터가 없어서 모형이 이상하게 나올 것 같다
2. H3 셀 단위로 학습데이터가 만들어진 게 아닌 것 같다
3. H3 셀 centroid 기반으로 OTP를 재쿼리하여 학습 데이터를 재구축해야 한다

### 1.2 현재 상태 확인

현재 학습 데이터는 **정류장-정류장(stop-to-stop)** 단위로 구축되어 있다.

- `tcn_to_otp_od.py`에서 승/하차정류장 좌표를 직접 OTP에 전달
- OTP가 반환하는 경로의 출발지 = 정류장 바로 앞
- 따라서 access_time 중앙값 7초, egress_time 중앙값 9초 → 실제 퍼스트/라스트 마일이 아닌 OTP snap 거리

도보 피처가 완전히 0은 아니다. OTP가 인근 다른 정류장/지하철역을 경유하는 경로도 생성하기 때문에 access_time > 60초인 대안이 32.8% 존재하고, OD 내 대안 간 access_time 표준편차 > 60초인 경우도 42.5%이다. 다만 이 도보는 "정류장→다른 정류장" 간 도보이지, 이용자의 실제 출발지(집 등)에서 정류장까지의 퍼스트마일은 아니다.

### 1.3 핵심 문제 정리

| 문제                    | 설명                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| 퍼스트/라스트 마일 부재 | 이용자의 실제 출발지→정류장 도보가 모형에 반영되지 않음                                               |
| 정류장 선택이 모형 밖   | 같은 지역에서 버스정류장 vs 지하철역으로 가는 도보 차이가 경로선택에 큰 영향을 주지만, 현재 구분 불가 |
| 신규 인프라 평가 불가   | 새 정류장/노선(GTX 등) 도입 시, 기존 SC 경험적 빈도가 없어 수요 예측 불가                             |

## 2. 검토한 접근법들

### 접근법 A: H3 centroid에서 OTP 재쿼리

H3 셀 centroid 좌표로 OTP를 쿼리하여 퍼스트/라스트 마일이 포함된 경로를 생성하고, SC를 H3 OD 단위로 매칭하는 방법.

**문제점**: centroid 한 점에서 OTP가 생성한 경로와, 셀 내 각기 다른 정류장에서 실제 탑승한 SC 기록의 매칭이 근본적으로 어렵다. OTP는 centroid 기준 가까운 정류장/노선 위주로 경로를 생성하지만, 실제 이용자들은 각자 집 근처 정류장에서 탑승하므로, 출발 정류장과 노선이 모두 달라 유사도 매칭(mode, route, sequence)이 성립하기 어렵다.

### 접근법 B: 경로선택모형에 도보 피처 직접 포함

centroid→정류장 도보시간을 피처로 넣어 모형이 도보의 영향을 학습하도록 하는 방법.

**문제점**: centroid는 셀 내 대표점일 뿐이므로 centroid 편향이 발생한다. centroid에서 가까운 정류장의 도보시간이 과소 추정되고, 먼 정류장은 과대 추정된다. 셀 내 실제 인구 분포와 무관하게 centroid 위치가 도보 피처를 결정하므로, 모형 계수가 왜곡될 수 있다.

### 접근법 C: 도보 피처 제외 + SC 빈도로 배분

경로선택모형의 scope를 "정류장이 정해진 후의 경로 선택"으로 한정하고, 정류장 배분은 SC 경험적 빈도로 처리하는 방법.

**문제점**: 새 정류장이나 노선이 도입되면 SC 데이터가 없어 배분 확률을 알 수 없다. GTX 역 등 신규 인프라 평가가 불가능해진다.

## 3. 채택 방향: Empirical Bayes 정류장 배분 + 정류장 OD 경로선택모형

### 3.1 핵심 아이디어

모형을 두 단계로 분리한다:

```
[1] OD 생성 (H3 셀 단위)
     │
     ▼
[2] 정류장 배분 (Empirical Bayes)   ← 퍼스트/라스트 마일을 여기서 처리
     │
     ▼
[3] 경로선택 (정류장-정류장 모형)    ← 기존 모형 유지, SC 매칭 안정
     │
     ▼
[4] 네트워크 배분
```

- 경로선택모형 자체는 정류장-정류장으로 깔끔하게 유지 → SC 매칭률 저하 없음
- 퍼스트마일(도보)의 영향은 정류장 배분 단계에서 EB로 처리
- 신규 정류장(GTX 역)은 EB prior(도보 거리)로 배분 가능

### 3.2 Empirical Bayes 정류장 배분

#### Prior: 도보 거리 기반 감쇠 함수

```
P_prior(정류장 k | H3 셀 i) ∝ exp(-β · distance(centroid_i, stop_k))
```

- β: 도보 거리 감쇠 파라미터 (SC 전수 데이터에서 추정)
- distance: centroid에서 정류장까지의 네트워크 도보 거리

#### Likelihood: SC 관측 빈도

```
L(정류장 k | H3 셀 i) = n_ik / Σ_j n_ij
```

- n_ik: 셀 i 내에서 정류장 k를 이용한 SC 관측 건수

#### Posterior: Prior + Likelihood 결합

```
P_posterior(정류장 k | H3 셀 i) ∝ P_prior(k|i) · L(k|i)
```

#### 상황별 작동 방식

| 상황                     | SC 데이터      | posterior 특성                               |
| ------------------------ | -------------- | -------------------------------------------- |
| 기존 정류장 (SC 풍부)    | n_ik = 500건   | SC 관측 빈도에 수렴 (likelihood 지배)        |
| 기존 정류장 (SC 부족)    | n_ik = 3건     | prior(도보 거리) 쪽으로 이동                 |
| **GTX 신설역 (SC 없음)** | **n_ik = 0건** | **posterior = prior (도보 거리만으로 배분)** |

### 3.3 β 파라미터 추정

SC 전수 데이터에서 경험적으로 추정:

1. 모든 H3 셀에 대해 (centroid → 셀 내 각 정류장 거리, 해당 정류장 SC 이용 건수) 쌍을 추출
2. 거리-이용빈도 관계를 지수 감쇠 함수로 피팅 (MLE)
3. 피팅된 β가 Empirical Bayes의 "경험적(empirical)" 부분

```python
import numpy as np
from scipy.optimize import minimize_scalar

def neg_log_likelihood(beta, distances, counts):
    probs = np.exp(-beta * distances)
    probs = probs / probs.sum()
    return -np.sum(counts * np.log(probs + 1e-10))

result = minimize_scalar(neg_log_likelihood, bounds=(0.001, 0.05),
                         method='bounded', args=(distances, counts))
beta_hat = result.x
```

### 3.4 이 방향의 장점

| 항목             | 설명                                                   |
| ---------------- | ------------------------------------------------------ |
| SC 매칭 안정성   | 기존 정류장 OD 매칭을 그대로 유지                      |
| GTX 평가 가능    | EB prior로 신설역에 대한 수요 배분 가능                |
| 모형 분리 명확   | 정류장 배분(도보)과 경로선택(경로 속성)의 scope가 분명 |
| 리뷰어 방어 용이 | choice_prob과 피처의 OD 단위가 일관됨                  |

### Phase 2: Empirical Bayes 정류장 배분 모형

| 단계 | 작업                                             | 산출물                      |
| ---- | ------------------------------------------------ | --------------------------- |
| 2-1  | 셀-정류장 간 네트워크 도보거리 계산 (OSRM foot)  | `h3_stop_walk_distance.csv` |
| 2-2  | SC 이용빈도 ~ 도보거리 관계 분석 및 β 추정 (MLE) | β 값, 피팅 결과 시각화      |
| 2-3  | Prior 계산: exp(-β · distance)                   | `h3_stop_prior.csv`         |
| 2-4  | Posterior 계산: Prior × SC Likelihood            | `h3_stop_posterior.csv`     |
| 2-5  | 검증: posterior vs SC 관측빈도 비교              | 검증 결과 리포트            |

```python
def compute_posterior(prior_probs, sc_counts, alpha=1.0):
    """
    prior_probs: exp(-β · distance), normalized
    sc_counts: SC 관측 건수
    alpha: prior 강도 (하이퍼파라미터)
    """
    posterior = alpha * prior_probs + sc_counts
    return posterior / posterior.sum()
```

## 7. 논문에서의 포지셔닝

### 연구 기여

1. **SC 전수 데이터 + Raptor 기반 choice set + H3 존 집계**를 결합한 대규모 RP 경로선택 확률 구축 방법론
2. **Empirical Bayes 정류장 배분**: 기존 네트워크는 SC 관측 기반, 신규 인프라는 도보 거리 prior 기반으로 자연스럽게 전환되는 메커니즘
3. **GTX 영향평가**: 신설 노선에 대한 경로선택 변화 및 수요 전환 분석

### Limitation으로 명시할 사항

- 정류장 배분의 prior는 centroid 기반 도보 거리이므로, 셀 내 인구 분포를 직접 반영하지 못함
- SC 데이터가 없는 완전히 새로운 지역에서는 β의 이전 가능성(transferability) 추가 검증 필요
- SC는 승/하차 정류장만 기록하므로, 이용자의 실제 출발지와의 대조 검증 불가
- 경로선택모형은 대중교통 내 경로선택만 다루며, 수단선택(자가용 vs 대중교통 등)은 포함하지 않음

## 8. 확장 방향 개요

현재 EB 정류장 배분 구조의 핵심 강점은 **입력 해상도와 모형 해상도가 분리**되어 있다는 점이다. 이 구조를 그대로 유지하면서, 데이터 소스와 수단 유형을 확장할 수 있다.

```
[입력 레이어]                       [배분 레이어]                [선택 모형]

위경도 포인트 (통신사/GPS) ──┐
                           ├──→ 접근점 배분 (EB) ──→ 수단/경로선택모형
H3 셀 (SC 집계) ───────────┘     + 수단별 접근점             (Attention)
```

EB 배분 레이어가 **해상도 변환기(adapter)** 역할을 한다. 위경도 포인트가 들어오든 H3 셀이 들어오든, "어떤 접근점을 이용할 것인가"로 변환하면 뒤의 선택 모형은 동일한 입력을 받는다.

## 9. 데이터 소스 확장

| 데이터           | 역할                                        | 해상도        | 시점      |
| ---------------- | ------------------------------------------- | ------------- | --------- |
| SC (현재)        | 경로선택 choice_prob + β 추정               | H3 집계       | GTX 과제  |
| 통신사 RP        | 멀티모달 수단선택 + 정확한 OD + β_mode 추정 | 위경도 포인트 | 향후 연구 |
| DTUMOS SP (GSRP) | 신규 수단/서비스 선호도, 교차탄력성         | 위경도 포인트 | 향후 연구 |

### 위경도 포인트 입력 시 EB의 변화

통신사 데이터는 개별 위경도가 있으므로, EB prior의 centroid 편향이 제거된다. 모형 구조 변경 없이 데이터 품질 향상만으로 성능이 올라가는 구조이다.

```
SC (현재):     prior = exp(-β · dist(centroid, stop))         ← centroid 편향
통신사 (향후): prior = exp(-β · dist(actual_origin, stop))    ← 실제 출발지
```

## 10. 멀티모달 확장: 정류장 배분 → 접근점 배분

택시, 공유킥보드 등을 포함하면 **접근점(access point) 배분**으로 일반화된다.

```
접근점 유형:
  - 버스정류장   (도보 접근)
  - 지하철역     (도보 접근)
  - 택시 승차점  (도보 or 호출, 대기시간 포함)
  - 공유킥보드   (도보 접근, 가용성 확률 포함)

Prior 일반화:
  P(접근점 k | 출발지) ∝ exp(-β_m · cost_k)

  β_m  = 수단 m별 감쇠 파라미터
  cost_k = 수단별 접근 비용 함수
```

β_m이 수단별로 다르게 추정되면, "지하철역까지 10분 걷기 vs 택시 호출 3분 대기"의 트레이드오프를 포착할 수 있다.

## 11. Attention 기반 선택 모형과의 연결

EB 배분의 출력(access/egress cost)을 대안 피처로 입력할 수 있다.

```
대안 구성 예시 (멀티모달):

[대안 1] 도보3분 → 버스100 → 환승 → 지하철3호선 → 도보5분
[대안 2] 도보8분 → 지하철2호선 → 도보2분
[대안 3] 택시호출2분 → 택시 15분 → 도보1분
[대안 4] 도보2분 → 킥보드5분 → 지하철2호선 → 도보2분

각 대안의 피처 벡터:
  [access_cost, transit_time, fare, transfers, egress_cost, reliability, ...]
       ↑                                              ↑
   EB 배분에서 산출                                EB 배분에서 산출
```

### 단계적 통합 로드맵

| 단계       | 구조                        | 설명                               |
| ---------- | --------------------------- | ---------------------------------- |
| 현재 (GTX) | EB 배분 → 경로선택 (분리)   | 두 단계 독립 추정                  |
| 중기       | EB 기대비용을 피처로 입력   | access_cost = Σ_k P(k) · cost_k    |
| 장기       | End-to-end joint estimation | 접근점 배분과 경로선택을 동시 학습 |

### 지금 EB 구현 시 확장을 위해 신경 쓸 점

당장 복잡하게 만들 필요는 없지만, 다음을 염두에 두고 코드를 짜면 나중에 수정이 적다:

1. **EB 모듈의 입력을 `(출발지 좌표, 접근점 목록, 거리)` 형태로 일반화** — 지금은 (centroid, 정류장, 도보거리)이지만, 향후 (위경도, 택시승차점, 호출대기시간) 등으로 확장 가능하도록
2. **β를 접근점 유형별로 분리 가능한 구조** — 지금은 β 하나이지만, `beta_dict = {'walk': β}` 형태로 두면 나중에 `'taxi': β_taxi` 추가가 쉬움
3. **비용 함수를 플러그인 가능하게** — 지금은 `exp(-β · distance)`이지만, 함수를 인자로 받는 구조로 두면 택시 비용 함수 등 교체 가능
