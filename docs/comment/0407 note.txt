2026.04.07 미팅 정리 (여지호 교수님 + 김민수)

-----------------------------------------------------------------
핵심 결정사항

1. IVT는 Total IVT (수단 합산)로 최종 확정
   - IVT를 bus/train/gtx로 분리하면 train, gtx의 beta가 양수로 나옴
   - 원인: 주력 수단 IVT와 환승 횟수 간 구조적 상관 (structural collinearity)
   - 교수님: "인비클 트래블 타임 하나로만 넣으면 음수로 나오는 거 아니에요? 그럼 이대로 갑시다"
   - Total IVT는 MNL/ML/TasteNet 모두 음수(정상) 확인됨

2. 학습 데이터 구축 마무리, 모델 배정(assignment) 단계로 전환

-----------------------------------------------------------------
논문에 추가할 분석

1. 경로 선택 확률 분포 분석
   - Raptor가 제시하는 후보 경로들(choice set)에 대해 선택 확률 배정
   - 사람들이 어떤 기준으로 선택하는지 해석:
     * generalized cost 최소화 vs 환승 최소화 vs 도보 최소화
     * 네이버/구글처럼 "최소 환승", "최소 비용", "최소 도보" 옵션별 선택 비율
   - Top-1, Top-3 정확도에서 어떤 정렬 기준이 실제 선택과 가장 일치하는지

2. Raptor 알고리즘 파라미터 보정 (calibration)
   - 학습된 모델의 선택 패턴에 맞춰 Raptor의 generalized cost 가중치 조정
   - SC 데이터 기반 선택 분포 → Raptor 출력이 비슷하게 나오도록 보정
   - 보정 후 확률 배정까지 수행

3. Raptor bucketing 최적화 (교수님 구현 완료)
   - 시간 단위(5분 등) / H3 셀 레벨 단위로 묶어서 돌릴 수 있음
   - agent-based (point-to-point)도 가능
   - 적정 셀 레벨 결정 필요 → 논문 contribution으로 활용

-----------------------------------------------------------------
한계점 (논문 Limitation에 기술)

1. 버스 통행시간이 실시간(혼잡) 반영이 안 됨
   - GTFS 기반 계획  시간만 사용 중
   - 같은 시간이어도 지하철을 더 선호하는 경향 존재 (신뢰성 차이)
   - 후속 연구: 실시간 버스 데이터 파싱 → 모델 고도화

2. IVT 수단 분리 불가
   - structural collinearity로 인해 수단별 시간가치 식별 불가
   - 서브 섹션으로 분석 과정/원인만 기술 (연구의 최적해는 아님을 명시)

-----------------------------------------------------------------
후속 연구 아이디어 (교수님)

1. 수상택시 (한강버스): 영국 GTFS 공개 데이터 → 런던 vs 서울 비교
   - 오세훈 시장 벤치마킹 배경, 왜 영국에서는 되고 한국에서는 안 되는지
2. Mode choice 연구
3. 대중교통 네트워크 최적화
4. DRT: 기존 버스 노선 대체 가이드라인 (버스+DRT 통합 최적화)
5. 실시간 버스 데이터 반영 모델 (모델 자체 논문)
