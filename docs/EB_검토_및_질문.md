# EB 정류장 배분 방법 검토 및 실험 결과

---

## 1. 교수님 제안 구조 이해

모형을 두 단계로 분리:

```
[1단계] EB 정류장 배분: H3 셀 → 어느 정류장으로 갈까? (walk 처리)
[2단계] 경로선택모형:   정류장 → 정류장 어떤 경로 탈까? (기존 모형 유지)
```

- 1단계에서 도보(walk)의 영향을 EB로 처리하고, 2단계 경로선택모형은 기존 정류장 OD 모형을 그대로 사용
- GTX 신설역은 SC 데이터가 없으므로 EB prior(도보 거리)만으로 배분

### EB 구조

```
Prior:      exp(-β × 도보거리)   → "가까우면 갈 확률 높다"
Likelihood: SC 관측 인원수        → "실제로 몇 명이 탔다"
Posterior:  Prior × Likelihood   → "최종 배분 확률"

- SC 풍부 → SC 관측 비율을 따름
- SC 부족 → 도보 거리(prior) 쪽으로 이동
- SC 없음 (GTX 신설역) → prior = posterior
```

### 적용 흐름

```
H3 셀 → H3 셀: 1000명 통행

[1단계] EB 배분:
  GTX역:      100명
  지하철역:    700명
  버스정류장:  200명

[2단계] 각 정류장에서 경로선택모형 적용:
  GTX역 100명 → GTX직통 80명, GTX+환승 20명
  지하철역 700명 → 2호선+1호선 490명, 2호선+버스 210명
  버스정류장 200명 → 버스100 120명, 버스200 80명
```

실제 데이터를 확인하면 OTP가 인근 다른 정류장/지하철역을 경유하는 경로도 반환하고 있어서 도보 피처에 상당한 변동이 있습니다.

| access_time > 60초인 대안 비율       | 32.8% |

### 2.2 학습 데이터는 Raptor 경로 기반

학습 데이터의 경로(대안 셋)는 OTP Raptor 알고리즘으로 생성한 것이며, 스마트카드는 경로 생성이 아닌 선택확률(choice_prob) 산출에 사용했습니다. 학습과 모형 적용 모두 정류장 to 정류장 기준으로 수행했습니다.

## 6. EB walk 이중 반영 문제

EB가 "어느 정류장으로 갈까"를 처리하고, 경로선택모형에도 다른 정류장으로 걸어가는 대안이 포함되어 있어 이중 반영이 우려되었으나, 실제로는 **다른 단계의 의사결정**임을 확인하였습니다.

```
[EB] "어느 정류장 근처로 갈까?" → 정류장 레벨 변수 (centroid→정류장 거리)
[모형] "정류장A에서 바로 탈까, 지하철역B로 걸어갈까?" → 경로 레벨 변수 (OTP walk)
```

실험으로도 확인: EB 피처를 MNL에 넣으면 β=0이 됨 → MNL이 경로 레벨에서만 작동하므로 정류장 레벨 변수는 흡수되지 않음. 따라서 이중 반영이 아닙니다.

## 9. 핵심 발견 요약

### 구조적 한계

1. **EB 피처(거리, 노선수)는 MNL에 넣어도 β=0** — 정류장 레벨 변수는 경로 레벨 MNL에서 변별력 없음
2. **OTP walk 제거 시 성능 큰 하락** (ρ² 0.53→0.47) — EB 피처가 대체 못함
3. **EB 거리 β≈0** — 정류장 선택에서 도보 거리보다 **노선 연결성**이 핵심 요인
4. **접근 도보 VoWT 과대추정** — SC 구조(선택된 경로 walk≈0)에 의한 편향

### SC 기반 walk의 딜레마

```
OTP walk 넣으면 → 성능 좋음 (ρ²=0.53) → 근데 VoWT 과대추정
OTP walk 빼면   → 성능 하락 (ρ²=0.47) → EB 피처가 대체 못함
EB walk 넣으면  → β=0                  → 변별력 없음
```

SC 데이터가 정류장에서 시작하는 한, walk을 깔끔하게 처리하는 것은 구조적으로 어렵습니다.

## 10. 권장 구조

```
경로선택모형: 정류장 OD + OTP walk 포함 (기존 모형, ρ²=0.53) → 그대로 유지
EB 정류장 배분: 적용 단계에서만 사용 (M2 prior: 거리 + 노선 수)
접근점 그룹화: 같은 위치 정류장(100m 이내)을 하나의 접근점으로 묶음 (34K→16K)
```

- MNL 자체는 기존과 동일 (피처 9개, 계수 동일)
- EB는 MNL 앞에 붙는 적용 단계 전처리 모듈
- walk은 모형의 한계로 인정하고 limitation에 명시

### 향후 검토 사항

- 노선 수 β가 음수(-0.378)인 원인 분석 필요
- Nested Logit으로 정류장 레벨/경로 레벨 계층 구조 모형화
- 가구통행실태조사 교차 검증으로 walk 파라미터 신빙성 보강
- GTX-A SC 패턴을 활용한 GTX-B/C/D prior 보정
