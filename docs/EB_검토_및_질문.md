# EB 정류장 배분 방법 검토 및 질문 정리

---

## 1. 교수님 제안 구조 이해

모형을 두 단계로 분리:

```
[1단계] EB 정류장 배분: H3 셀 → 어느 정류장으로 갈까? (walk 처리)
[2단계] 경로선택모형:   정류장 → 정류장 어떤 경로 탈까? (기존 모형 유지)
```

- 1단계에서 도보(walk)의 영향을 EB로 처리하고, 2단계 경로선택모형은 기존 정류장 OD 모형을 그대로 사용
- GTX 신설역은 SC 데이터가 없으므로 EB prior(도보 거리)만으로 배분

### EB 구조

```
Prior:      exp(-β × 도보거리)   → "가까우면 갈 확률 높다"
Likelihood: SC 관측 인원수        → "실제로 몇 명이 탔다"
Posterior:  Prior × Likelihood   → "최종 배분 확률"

- SC 풍부 → SC 관측 비율을 따름
- SC 부족 → 도보 거리(prior) 쪽으로 이동
- SC 없음 (GTX 신설역) → prior = posterior
```

### 적용 흐름

```
H3 셀 → H3 셀: 1000명 통행

[1단계] EB 배분:
  GTX역:      100명
  지하철역:    700명
  버스정류장:  200명

[2단계] 각 정류장에서 경로선택모형 적용:
  GTX역 100명 → GTX직통 80명, GTX+환승 20명
  지하철역 700명 → 2호선+1호선 490명, 2호선+버스 210명
  버스정류장 200명 → 버스100 120명, 버스200 80명
```

## 2. 기존 학습 데이터 확인 사항

### 2.1 도보 피처는 "거의 0"이 아님

교수님께서 도보 피처가 없다고 말씀하셨는데, 실제 데이터를 확인하면 OTP가 인근 다른 정류장/지하철역을 경유하는 경로도 반환하고 있어서 도보 피처에 상당한 변동이 있습니다.

| 피처 | 중앙값 | 75%ile | 평균 |
|------|--------|--------|------|
| access_time | 7초 | 125초 | 89초 |
| egress_time | 9초 | 149초 | 97초 |
| walk_distance | 242m | 482m | 301m |
| walk_time | 202초 | 402초 | 251초 |

| 지표 | 값 |
|------|-----|
| access_time > 60초인 대안 비율 | 32.8% |
| OD 내 대안 간 access_time std > 60초 | 42.5% |

현재 MNL 추정 결과에서도 access/egress가 유의하게 추정되었습니다:
- β_access = -3.190 (t = -1575.51)
- β_egress = -2.083 (t = -1556.31)

### 2.2 학습 데이터는 Raptor 경로 기반

학습 데이터의 경로(대안 셋)는 OTP Raptor 알고리즘으로 생성한 것이며, 스마트카드는 경로 생성이 아닌 선택확률(choice_prob) 산출에 사용했습니다. 학습과 모형 적용 모두 정류장 to 정류장 기준으로 수행했습니다.

## 3. 검토 과정에서의 질문

### Q1. EB 구조 채택 시 경로선택모형의 walk 피처 처리

EB가 1단계에서 도보 거리 기반으로 정류장 배분을 처리하므로, 2단계 경로선택모형에서는 기존의 access_time/egress_time 피처를 제거하는 것이 일관적이라고 생각합니다. EB가 이미 퍼스트/라스트 마일 도보를 반영했는데, 경로선택모형에서 다시 도보 시간이 들어가면 walk의 영향이 이중으로 반영되기 때문입니다.

다만 현재 β_access (-3.19, t=-1575), β_egress (-2.08, t=-1556)이 유의하게 추정되어 있어서, 제거 시 모형 성능 변화를 확인해볼 필요가 있습니다.

### Q2. GTX역과 기존 지하철역이 같은 위치일 때 EB 배분 및 GTX 확장

GTX역이 기존 지하철역에 병설되는 경우(강남역 등), H3 centroid에서의 도보 거리가 거의 동일하므로 EB prior가 비슷하게 나옵니다.

```
강남역(지하철): centroid에서 400m → prior ≈ 0.33
강남역(GTX):   centroid에서 400m → prior ≈ 0.33
```

물리적으로 같은 장소에서 지하철과 GTX 중 무엇을 탈지는 "어느 정류장으로 걸어갈까"의 문제가 아니라 "어떤 경로를 탈까"의 문제이므로, 같은 역은 하나의 접근점으로 묶고 GTX vs 지하철 선택은 경로선택모형에서 처리하는 것이 맞는지 확인이 필요합니다.

또한 현재 SC에 GTX-A 데이터가 이미 있으므로 GTX-A는 likelihood가 존재합니다. 향후 GTX-B/C/D 신설 시에는 SC가 없어 prior만으로 배분하게 되는데, GTX-A의 SC 패턴을 GTX-B/C/D의 prior 보정에 활용할 수 있는지도 검토해볼 수 있을 것 같습니다.

## 4. EB 구현 및 실험 결과

### 4.1 구현 완료 사항

| Phase | 내용 | 결과 |
|---|---|---|
| Phase 1 | H3 매핑 + OSRM 네트워크 도보거리 | 4,801셀, 셀당 7.2개 정류장, 평균 482m |
| Phase 2 | β 추정 (MLE) + EB prior/posterior | β=0.000105, SC 있는 셀 3,852개, 없는 셀 949개 |
| Phase 3 | H3 OD choice_prob 재집계 + EB walk 피처 부여 | 526,968 정류장 OD → 261,359 H3 OD |
| OSRM | Docker로 한국 foot routing 서버 구축 | localhost:5000 |

- β = 0.000105: 도보거리 100m 증가 시 이용확률 약 1.0% 감소
- OSRM 네트워크 거리는 직선거리의 약 1.8배

### 4.2 5가지 MNL 모형 비교

| 모형 | Train ρ² | Test ρ² | Top-1 | 피처수 |
|---|---|---|---|---|
| **1. 정류장 OD + OTP walk** | 0.5328 | **0.5304** | **72.5%** | 9 |
| 2. 정류장 OD - walk | 0.3237 | 0.3212 | 60.8% | 6 |
| **3. H3 OD + OTP walk** | 0.4802 | **0.5249** | **67.2%** | 9 |
| 4. H3 OD + EB walk (OSRM) | 0.4046 | 0.4732 | 58.7% | 8 |
| 5. H3 OD - walk | 0.4046 | 0.4732 | 58.7% | 6 |

### 4.3 주요 발견

**(1) OTP walk은 유효하고, EB walk(OSRM centroid→정류장)은 무효**

- 1번(정류장 OD + OTP walk)이 가장 높은 성능 (ρ²=0.53, Top-1=72.5%)
- 4번에서 EB walk 피처(ln_eb_access, ln_eb_egress)의 β가 모두 0.000으로 추정됨
- 4번과 5번의 결과가 동일 → EB walk 피처가 모형에 기여하지 못함

**(2) EB walk이 안 먹히는 이유: 경로 간 변별력 부재**

H3 centroid→정류장 거리는 **같은 정류장에서 출발하는 모든 경로에 동일한 값**이 할당됩니다. MNL은 대안 간 피처 차이로 선택을 설명하는데, 같은 정류장 출발 경로들의 EB walk이 동일하므로 변별력이 없습니다.

```
정류장a1에서 출발하는 경로 3개:
  경로1: eb_access = 400m
  경로2: eb_access = 400m (같음)
  경로3: eb_access = 400m (같음)
→ MNL에서 구분 불가
```

반면 OTP walk은 경로마다 경유 정류장이 달라 access_time이 다르게 나옵니다.

**(3) walk 제거 시 성능 하락이 큼**

- 정류장 OD: ρ² 0.53 → 0.32 (walk 제거 시 -0.21)
- H3 OD: ρ² 0.52 → 0.47 (walk 제거 시 -0.05)
- walk 피처가 모형 성능에 큰 기여를 하고 있음

**(4) SC 데이터 기반 walk의 근본적 한계**

| 방식 | walk 경로 간 변별력 | 한계 |
|---|---|---|
| OTP walk (정류장 OD) | 있음 (다른 정류장 경유) | 선택된 경로는 항상 ≈ 0 |
| OTP walk (H3 OD) | 있음 (위와 동일) | H3로 뭉개져서 효과 희석 |
| EB walk (OSRM) | 없음 (같은 정류장 = 같은 값) | MNL에서 구분 불가 |

SC 데이터가 정류장에서 시작하는 한, walk의 변별력 문제는 어떤 구조로든 완전히 해결되지 않습니다.

## 5. 결론 및 향후 방향

### 권장 구조

```
경로선택모형: 정류장 OD + OTP walk 포함 (기존 모형, ρ²=0.53) → 그대로 유지
EB 정류장 배분: 적용 단계에서만 사용 (GTX 신설역 수요 배분)
```

- 경로선택모형에서 walk을 제거하지 않고 기존 모형을 유지
- EB는 H3 셀 수요를 정류장으로 배분하는 **적용 단계 전처리 모듈**로 활용
- walk은 모형의 한계로 인정하고 limitation에 명시

### 정리

| 항목 | 내용 |
|------|------|
| 기존 모형 | 정류장 OD + OTP walk, ρ²=0.53, Top-1=72.5% → 유지 |
| EB 역할 | 적용 단계에서 정류장 배분 (특히 GTX 신설역) |
| walk 한계 | SC 기반이므로 선택된 경로의 walk ≈ 0은 구조적 한계, H3/EB로도 해결 안 됨 |
| 확인 필요 | 동일 위치 역 처리, GTX-A 패턴 활용 가능성 |
