# H3 Centroid OTP 경로선택모형 실험 결과

## 1. 배경 및 목적

기존 경로선택모형은 **정류장 OD 단위**로 OTP 경로를 생성하여 학습했습니다. 이 경우 출발 정류장이 고정되어 있어 access_time(접근 도보시간)이 모든 대안에서 동일하게 나타나고, 결과적으로 β_access를 추정할 수 없는 구조적 한계가 있었습니다.

이를 해결하기 위해 **H3 셀 중심점(centroid)을 출발/도착지로 사용하여 Raptor 경로를 새로 생성**하는 방식을 시도했습니다. OTP/Raptor가 centroid에서 주변 여러 정류장까지의 도보 경로를 자동으로 생성하므로, 대안별로 access_time에 자연스러운 변이(variation)가 발생합니다.

## 2. 파이프라인

```
[Step 1] H3 OD 입력 생성
  - 기존 SC 통행이 있는 261,359개 H3 OD 추출
  - 각 H3 셀의 centroid 좌표를 출발/도착 좌표로 사용
  - departure_time: 해당 H3 OD에서 가장 통행이 많은 시간대

[Step 2] Raptor 경로 탐색
  - MC-Raptor (Multi-Criteria) 실행
  - 설정: maxResults=15, maxAccessWalk=800m, maxAccessStops=30
  - 입력 261,359 OD → 257,716 OD에서 경로 생성 (98.6%)

[Step 3] OTP 캐시 빌드
  - Raptor 결과 JSON(9GB) → SQLite 캐시
  - 경로 중복 제거(deduplicate) 후 피처 추출
  - 257,716 H3 OD, 평균 4.1개 대안/OD

[Step 4] SC 매칭
  - TCN 7일치(2025.02.17~23) 스마트카드 데이터
  - stop OD → H3 OD 매핑 후, Raptor 경로와 3-Level 유사도 매칭
    (composite = 0.39×mode + 0.40×route + 0.21×sequence)
  - 매칭 threshold 민감도 분석 실시 (0.5 / 0.7 / 0.8 / 0.9)

[Step 5] MNL 추정
  - H3 OD 단위 choice_prob 집계
  - K3 사양 (9피처): IVT, access, egress, transfer walk, transfers, fare, mode dummies
  - Train/Test split: 80/20 (H3 OD 단위)
```

## 3. 핵심 개선: access_time 변이

|                                      | 이전 (stop OD → H3 매핑) |      H3 Centroid OTP       |
| ------------------------------------ | :----------------------: | :------------------------: |
| access_time 변이 있는 H3 OD 비율     |          27.3%           |         **74.9%**          |
| access_time std (변이 있는 OD)       |          ~1.3분          |         **1.4분**          |
| 선택 대안 vs 비선택 대안 access 차이 |       3m (무의미)        | **-10초 (선택이 더 짧음)** |

이전에는 같은 정류장에서 출발하는 대안끼리만 비교되어 access_time이 동일했으나, H3 centroid에서 OTP를 실행하면 주변 여러 정류장으로의 도보 경로가 자동 생성되어 대안별 access_time에 자연스러운 차이가 발생합니다.

## 4. SC 매칭 Threshold 민감도 분석

유사도 매칭 시 threshold를 얼마로 설정할지에 따라 매칭 품질과 데이터 규모가 달라집니다. composite similarity의 하위 지표 특성을 분석하여 적절한 threshold를 결정했습니다.

### 유사도 구간별 하위 지표 분석

| composite 구간 | 비율  | mode 평균 | route 평균 | sequence 평균 | 해석                                    |
| :------------: | :---: | :-------: | :--------: | :-----------: | --------------------------------------- |
|    0.9~1.0     | 56.5% |   1.00    |    1.00    |     0.91      | 노선+정류장 일치, 확실한 매칭           |
|    0.8~0.9     | 14.8% |   1.00    |    0.86    |     0.54      | 노선 대부분 일치, 정류장 약간 다름      |
|    0.7~0.8     | 10.1% |   1.00    |    0.66    |     0.50      | 노선 부분 일치                          |
|    0.5~0.7     | 18.7% |   0.92    |    0.25    |     0.61      | **노선 거의 불일치 (route=0 비율 42%)** |

- composite = 0.39×mode + 0.40×route + 0.21×sequence
- mode+route가 모두 1이면 composite ≥ 0.79 보장
- **0.5~0.7 구간의 42%는 route_score=0** → 다른 노선번호에 chosen=1이 붙을 수 있어 매칭 신뢰도가 낮음

### Threshold별 MNL 결과

| Threshold | 매칭 통행 수 |   H3 ODs |    ρ²     |   Top-1   |   Top-3   |  β_access  |  β_egress  | access 차이 |
| :-------: | -----------: | -------: | :-------: | :-------: | :-------: | :--------: | :--------: | :---------: |
|    0.5    |      32,008K |     231K |   0.271   |   58.4%   |   92.2%   |   -0.631   |   -0.618   |    -10s     |
|  **0.7**  |  **25,358K** | **198K** | **0.361** | **59.3%** | **92.8%** | **-0.970** | **-0.793** |  **-10s**   |
|    0.8    |      22,095K |     176K |   0.366   |   59.7%   |   93.5%   |   -0.995   |   -0.861   |    -12s     |
|    0.9    |      17,218K |     137K |   0.371   |   58.3%   |   94.4%   |   -1.039   |   -0.879   |    -15s     |

**관찰:**

- threshold를 높일수록 **ρ²가 개선** (0.271 → 0.371): 노이즈가 제거되면서 모형 적합도 향상
- **β_access 절대값 증가** (-0.63 → -1.04): 매칭 품질이 좋은 데이터만 남으면서 접근 도보의 효과가 더 뚜렷하게 나타남
- Top-1은 threshold 0.7~0.8에서 최고 (59.3~59.7%), 0.9에서는 데이터 감소로 소폭 하락
- Top-3는 threshold가 높을수록 꾸준히 개선 (92.2% → 94.4%)

**Threshold 0.7 선정 근거:**

- ρ²가 0.271 → **0.361로 대폭 개선** (0.8 대비 0.005 차이로 미미)
- Top-1 **최고 수준** (59.3%)
- 매칭 통행 25.4M으로 충분한 데이터 규모 유지
- 0.7 미만 구간의 route_score 불일치 문제 제거

### 이전 실험과의 비교

이전에 stop OD를 H3로 매핑한 후 외부 거리(OSRM)를 피처로 추가한 실험에서는:

| Feature        |     이전 (H3 매핑 + ext)     | 현재 (H3 Centroid OTP)  |
| -------------- | :--------------------------: | :---------------------: |
| β_access       | **+0.058 (양수, 이론 반대)** | **-0.970 (음수, 정상)** |
| β_egress       |        +0.100 (양수)         |      -0.793 (음수)      |
| 제약 활성 여부 |      제약에 걸림 (β=0)       |       걸리지 않음       |

이전 방식에서 양수가 나온 이유는, stop OD를 합쳐도 같은 정류장에서 출발하는 대안끼리의 access가 동일하여 변이가 없었기 때문입니다. H3 centroid에서 Raptor를 실행하면 출발지가 정류장이 아닌 셀 중심점이므로, OTP가 다양한 정류장으로의 도보 경로를 자동 생성하여 변이가 발생합니다.

### 모형 성능 비교

| 모형                                |    ρ²     | Test Top-1 | Test Top-3 |
| ----------------------------------- | :-------: | :--------: | :--------: |
| Stop OD K3 (기존)                   | **0.530** | **72.5%**  |    ~95%    |
| H3 매핑 + OTP walk (이전)           |   0.318   |   56.5%    |   85.4%    |
| **H3 Centroid OTP (현재, thr=0.7)** |   0.361   |   59.3%    | **92.8%**  |

- ρ²는 0.361로 기존(0.530)보다 낮으나, **choice set 자체가 다르므로 직접 비교는 어렵습니다**
  - 기존: 정류장 OD별 최대 5개 대안 (동일 출발 정류장)
  - 현재: H3 centroid에서 최대 15개 대안 (다양한 출발 정류장 경유)
- 이전 H3 매핑 방식(0.318) 대비 **ρ² 0.043 개선**
- Top-3 정확도 85.4% → **92.8%**로 크게 개선

## 7. 요약 및 의의

1. **H3 centroid에서 Raptor를 실행하면 access_time에 자연스러운 변이가 생겨 β_access를 정상적으로 추정할 수 있습니다.**

2. β_access = -0.970 (음수, 유의): 접근 도보가 길수록 해당 경로를 선택하지 않는다는 이론적 예측과 일치합니다.

3. 이전 방식(stop OD를 H3로 매핑 + 외부 거리 추가)에서는 β_access가 양수(+0.058)로 나왔으나, 이는 같은 정류장 출발 대안끼리 access가 동일하여 발생한 구조적 문제였습니다. H3 centroid OTP 방식으로 이 문제를 해결했습니다.

4. SC 매칭 threshold 민감도 분석 결과, **threshold=0.7**이 매칭 품질과 데이터 규모 간 최적 균형점임을 확인했습니다.

5. 기존 Stop OD 모형 대비 ρ²는 낮지만, choice set 구성이 다르므로 직접 비교보다는 β 부호의 이론적 정합성과 해석 가능성에 초점을 맞추는 것이 적절합니다.

## 8. 향후 과제

- GTX 시나리오 적용: H3 centroid 기반 모형으로 GTX 개통 시 경로선택확률 변화 예측
- TasteNet 적용: 동일 데이터로 TasteNet 추정하여 MNL과 비교

- Threshold 0.7 적용 학습 데이터 저장 및 재현성 확보
